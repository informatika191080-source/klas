# ЦифроПоміч: перевірка інтерфейсу та логіки

Дата: 16 листопада 2026 року. Перевірено три практичні теми, вісім мережевих місій, лабораторію, навігацію, допомогу, звіти та резервне відновлення. Це експертна та технічна перевірка; спостереження за реальними учнями ще не проводилося.

## Виявлені проблеми та зміни

| Проблема | Реалізоване виправлення |
| --- | --- |
| Дві головні мапи, окремий короткий маршрут і повторні запрошення до лабораторії конкурували за увагу | Одна мапа тем; вісім мережевих місій відкриваються як одна з тем. Короткий маршрут, дубльована реклама та невикористаний вибір класів усередині гри прибрані |
| Головна кнопка завжди починала першу тему | Продовження останньої незавершеної активності, з переходом до іншої незавершеної після її виконання |
| Вибір відповіді в першій частині не позначав тему як розпочату | Статуси враховують часткові дії, а не тільки завершені частини |
| Три панелі героїв, локальні кнопки допомоги та спливні репліки дублювали одна одну | Спільне вікно БІПа з ролями Байта, Пікселя й Кібера; у завданні залишено компактні зображення команди |
| CSS приховував пояснення помилок старих симуляцій | Пояснення знову видно біля завдання, вони отримують фокус і не зникають за таймером |
| Складне меню й велика бічна панель відсовували завдання вниз на телефоні | Дві основні кнопки та меню «Ще»; інші місії доступні в закритому списку після завдання |
| Після вибору відповіді DOM перебудовувався, фокус губився | Фокус зберігається у межах того самого завдання; нова частина починається із заголовка. Додано перехід до завдання з клавіатури без зміни маршруту |
| Повторення або редагування завершеної теми зменшувало загальний поступ | Відмітку попереднього завершення збережено окремо від поточного етапу тренування |
| У майстерні вимоги розміщувалися після редактора | Замовлення видно перед афішею й інструментами |
| Лабораторія показувала готову правильну послідовність | Картки подано в іншому порядку. Правильні варіанти в багатовибіркових вправах також перемішано з іншими |
| Підсумки трьох тем змішувалися з дипломом мережевого курсу | Загальний лічильник охоплює всі місії; умови диплома явно стосуються восьми мережевих звернень |
| Незбережений текст можна було втратити при переході чи зміні звуку | Текст правила й пошукового запиту зберігається під час введення; перемикання звуку не перебудовує урок |
| Пошкоджений імпорт міг містити невідомі етапи чи неправильні типи відповідей | Перевіряються етапи та типи даних до імпорту; якщо основний запис не вдається, відновлюються попередні записи тем |
| На дуже вузькому екрані вікно БІПа могло трохи виходити за лівий край | Ширину обмежено із запасом для смуги прокручування; вікно має власне прокручування |
| Головний декоративний робот відсував вибір класу на телефоні | На вузькому екрані вибір класів показано без великої декоративної композиції |

## Порівняння з першоджерелами

Порівнювалися описані авторами навчальні механіки, а не зовнішнє оформлення чи весь функціонал цих платформ.

- Code.org: видимий поступ і доступність інструкцій. Для нашого порталу застосовано явні статуси, кращу читабельність і клавіатурний доступ. Вбудований Immersive Reader чи озвучення не додавалися.
  - https://support.code.org/hc/en-us/articles/115001347791-The-student-experience-on-CodeAI
  - https://support.code.org/hc/en-us/articles/15802388622861-CodeAI-Instruction-Panel-Immersive-Reading-Support
- Scratch: короткі практичні дії та послідовне відкриття можливостей. У майстерні вимоги поставлено перед діями, збережено власний видимий результат роботи.
  - https://scratch.mit.edu/help/studio/tips/howto/get-started-intro/
- Khan Academy: підказка під час виконання та пояснення після відповіді мають різні цілі. У нас підказки зібрані в БІПа, пояснення помилки залишається біля завдання; допомога не зменшує результат.
  - https://blog.khanacademy.org/how-should-people-practice-on-khan-academy/
- W3C WAI: зрозумілі кроки, підписи й пояснення поруч із дією. Це додаткові рекомендації щодо когнітивної доступності, а не твердження про сертифіковану відповідність WCAG.
  - https://www.w3.org/WAI/WCAG2/supplemental/patterns/o4p07-step-instructions/

## Перевірки

- `node tests/progression.cjs`: реальні обробники всіх восьми мережевих місій, 24 навчальні результати, неправильні дії, залежності від дослідження та дозволів; частковий поступ, рекомендація продовження, маршрути, повторення й перевірка імпортованих станів.
- `node tests/backup.cjs`: старі збереження, спільна резервна копія, відхилення некоректних результатів, відкат невдалого запису.
- `node tests/messages.cjs`: умови завершення повідомлень, комбіноване сприйняття, два слайди, перенесення прогресу й безпечне формування HTML-презентації.
- У браузері: виконання майстерні на ширині 390 пікселів, завершення презентації, пояснення неправильної відповіді в мережевій місії, повторення, клавіатурний фокус, завантаження та відновлення резервних копій в обидва боки, відображення диплома.
- Макети 320, 390, 768 пікселів і звичайний настільний екран. Горизонтальне переповнення мапи не виявлено. Це перевірка макетів, а не тестування на фізичних телефонах.
- Повний спільний `portal.css` збережено. Жоден навчальний ключ сховища не перейменовано.

## Межі перевірки

- Для 6–9 класів поки є лише оболонки розділів: навчального наповнення там ще немає. Ця зміна не створює нових уроків цих класів.
- Зберігання залишається локальним; автоматичної синхронізації між пристроями чи класного журналу немає.
- Потрібне пробне проходження з учнями: чи знаходять наступну дію без підказки вчителя, чи розуміють відмінність завдання й допомоги, чи можуть виправити помилку самостійно.
